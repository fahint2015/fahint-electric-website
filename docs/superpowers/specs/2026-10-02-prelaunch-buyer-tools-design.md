# 上线前采购体验优化：分批范围与第一批设计

日期：2026-10-02

## 已确认的边界

用户同意推进同行对比建议中可在当前网站完成的项目，但明确要求把询盘邮件直达和正式域名配置留到网站完成后。

- 本轮不配置邮件收件服务、SMTP、第三方表单服务或真实收件测试。
- 不改 DNS、CUSTOM_DOMAIN、VITE_SITE_URL、canonical 策略或站点地图域名。
- 不改变现有深蓝、蓝绿、浅灰及圆角体系，不进行全站重设计。
- 保留 Contact 的七个产品系列选项，不恢复成冗长的型号下拉。
- 不擅自接入统计、上传或客户管理等第三方服务。
- 不编造案例、客户 logo、证书范围、MOQ、交期、质保或安装适用性。
- 实施由主代理在当前项目分批完成，不创建子代理。先提供本地成果，不因本次同意而自动推送或部署。

## 路线选择

推荐采购流程优先：先修复客户已选配置在询价中的丢失，再建设资料与选型工具，最后拓展内容和正文预渲染。优点是现有浏览、选型和联系行为很快能连起来；搜索正文改善稍后交付。

备选为搜索与内容优先：先做正文预渲染、资源入口和指南，再补选型工具。优点是内容分发基础先完成；采购交接问题会保留更久。

采用推荐路线。整体拆成独立可验收的批次，每批实施前补齐对应的详细设计和计划，不把整个网站一次性重写。

## 后续分批顺序

1. **询价配置连续性（本文详细设计）**：型号、颜色、询价类型和来源产品页在产品页与联系页之间保持一致；仍使用现有邮件软件/复制信息方式。
2. **资料与选型工具**：集中 Resources 入口和现有文件；重点型号可打印/下载的规格摘要；USB 结构化筛选；同系列型号对比；再将已选型号合并为一张轻量询价清单。复用现有目录、数据和组件，不做支付购物车或会员系统。
3. **采购内容与抓取基础**：在已核实的资料范围内扩展应用配套、OEM 样品确认和质量流程内容，补 USB/灯控/面板采购指南；评估并实施与现有 Pages 构建兼容的正文预渲染，保持域名配置不变。

统计服务配置、隐私政策中的具体处理条款、公开客户案例和正式商业承诺依赖用户材料或服务选择。现在可完成页面组织和非敏感事件的本地接口设计，但不将尚未接入服务说成可用统计，不发布占位政策或空案例。

## 第一批：询价配置连续性

### 用户可见行为

客户在产品页选择颜色后，无论点击页首询价、手机询价按钮，还是进入完整联系页，表单旁都能看到当前型号和所选颜色。

未主动选择颜色时显示“未指定”，不把默认展示的白色照片当作客户已选配置。不增加报价、可供货或认证承诺。

完整联系页继续显示七个系列的下拉框，并在旁边显示已选型号/颜色的简洁摘要。客户可清除该产品上下文，回到普通系列询价。

生成邮件内容和“复制询价信息”均包含相同的系列、完整型号、已选颜色、询价类型及来源产品路径。邮件按钮仍明确说明是打开邮件软件，不显示“已收到询价”。

### 状态与数据传递

- 产品数据仍以现有 `products.js`、`catalogProducts.js` 为唯一型号来源，不复制目录数据。
- 产品页在父级维护询价所选颜色，供图片区和表单共享；图片浏览状态与询价颜色分开，浏览背面/尺寸图不应悄悄改掉订购颜色。
- 进入 Contact 的链接只携带产品标识、颜色标识和支持的询价类型；不在 URL 中携带姓名、邮箱、公司或客户需求。
- Contact 根据已发布产品验证标识并恢复产品上下文；来源产品路径由已验证产品生成，不接受任意外部来源 URL。
- 系列下拉仍是系列字段，型号是独立上下文字段，不能再用同一个字段在系列和型号之间互相覆盖。
- 切换产品/OEM/技术问题标签保留已验证的产品和颜色，所选询价类型进入邮件内容。
- 复用现有共享表单的验证、错误反馈、复制恢复以及超长邮件处理，不新增邮件发送路径。
- 不引入全局状态库，不将表单个人信息存入浏览器持久存储。

### 明确的边界行为

- 未知型号、草稿型号、无效颜色参数被忽略，不回显不可信文本。
- 颜色必须属于当前型号可选颜色；更换型号后不沿用前一型号颜色。
- 更换到其他系列或清除已选产品时清除旧型号/颜色摘要，保留用户已经填写的姓名、公司和需求。
- 同系列切换型号时采用新的型号上下文；没有新颜色时回到未指定。
- 普通 `/contact` 访问不显示虚构型号；原有不带产品的系列询价继续可用。
- 产品页内部锚点和手机按钮保持当前可用的滚动逻辑，不新增遮挡内容的浮动按钮。
- URL 中的特殊字符使用标准编码；输出通过 React 文本和已有邮件编码机制处理，不插入 HTML。

### 组件分工

- `src/components/products/ProductDetailHero.jsx`：接收有效的询价颜色选择及变更回调，继续维护图片展示。
- `src/pages/ProductDetail.jsx` 与 `src/pages/CatalogProductDetail.jsx`：提供各自产品的共享选择状态，为现有表单和联系页入口生成一致上下文。
- `src/pages/Contact.jsx`：验证查询参数，保留系列选择和询价类型，清除不再适用的型号/颜色。
- `src/components/InquiryForm.jsx`：展示精简配置摘要，统一生成邮件文本与复制文本，不新增发送服务。
- 如两种产品页需要共享编码/验证逻辑，仅提取一个小型询价上下文工具，不引入新的状态框架或全站重构。

### 验收

1. GFCI 型号和 USB 型号各覆盖一次“选择颜色 → 页面表单 → 完整联系页 → 生成询价文本”的流程。
2. 邮件与复制文本准确包含对应型号、颜色和需求类型，Contact 仍只有七个系列选项。
3. 无效型号/颜色、切换系列、切换型号、清除选择不会泄漏或误带前一产品信息。
4. 姓名、邮箱、公司和需求草稿不会因为标签或系列切换被无故删除。
5. 不配置邮件直达，不变更域名文件，不向真实邮箱发送测试信息。
6. 复用现有 Vitest/Testing Library，先补相关行为的失败用例再实现；完成后运行相关测试、必要回归和构建。
7. 浏览器可用时核对桌面与手机摘要布局、锚点及键盘访问；无法实测时如实标明，不以构建成功替代视觉验收。

## 自查

- 延后项与用户本轮要求一致。
- 不会把七系列下拉改回全型号列表。
- 功能层只解决配置连续性，邮件服务、资料中心、对比列表属于各自独立批次。
- 未确定的商业资料不以占位内容上线。
- 当前文档是实施前设计；需用户审阅后再生成第一批实施计划并开始修改网站代码。
