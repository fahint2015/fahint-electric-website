# 手机端性能：测量与最小加载优化

日期：2026-10-03

## 已确认的目标与边界

用户同意先实测首页、USB 列表、产品详情的手机慢网表现，再针对瓶颈调整。

- 不改变版式、配色、照片构图、文案或型号事实。
- 保留正文预渲染、无 JavaScript 的主体可读性，以及筛选、对比、询价清单的现有行为。
- 不改域名、邮件直达、统计配置，不推送或部署。
- 主代理在当前分支完成，不新增依赖或创建子代理。

## 当前证据

生产构建在本地预览中测试，390 × 844、冷缓存、1.6 Mbps 下载、150 ms 延迟、4 倍 CPU 限速，启用减少动态效果以排除自动轮播干扰。已跑两轮。下面是实验室结果，不是线上真实用户 Core Web Vitals，也不等于 PageSpeed 分数。

| 页面 | 主体最大内容出现（LCP） | 测量窗口内资源量 | JavaScript 传输量 | 初始布局偏移（CLS） |
| --- | --- | --- | --- | --- |
| 首页 | 3.64–3.78 秒 | 1,521 KiB | 175 KiB | 0.0001 |
| USB 列表 | 3.89–3.90 秒 | 671 KiB | 170 KiB | 0.0109 |
| FTR15-3100 详情 | 2.02–2.03 秒 | 739 KiB | 187 KiB | 0–0.0007 |

资源量使用浏览器 encodedBodySize，不把构建文件未压缩体积当作网络传输量。两轮中没有浏览器错误、警告或横向溢出；USB 筛选及手机菜单可用。菜单事件耗时观察值 24–104 ms，不据此宣称全站 INP 达标。

发现：

1. 首页尚未使用的两张轮播图仍会在首屏附近一起加载，原生 lazy 不会因为图片透明而自动推迟它们；首屏后多张照片也进入了浏览器的预加载距离。
2. 页面脚本请求在主入口完成后才开始。例如 USB 列表页依赖约在 2.4 秒启动，目录脚本约在 3.8 秒完成。
3. 主入口直接包含 Blog、BlogPost、About 和 Capabilities 等非当前页面的组件。
4. 完整目录确实被首页展示与询价组件引用，但目录分块传输仅约 61 KiB；目前证据不支持先大规模重构目录数据。

原始诊断脚本和一轮完整结果保存在忽略目录 `output/playwright/mobile-performance-probe.js`、`mobile-performance-before.json`。

## 方案比较与推荐

### A. 先调整资源加载路径（推荐）

- 首屏当前主图保留高优先级；后续海报和非关键图片降低优先级，避免争用首屏下载。优先使用浏览器原生能力，不引入自制图片加载框架。
- 将非当前内容页沿用现有 React.lazy / Suspense 模式按路由加载。
- 若复测确认脚本瀑布仍有明显影响，利用 Vite 构建清单，在对应静态页面预加载该路由必要的模块及其共享依赖；不预加载全站全部页面，不改共享样式的静态可用性。
- 分项调整、逐项复测。只保留有明确收益且无交互或抓取回归的修改。

优点：沿用现有技术栈、改动可控、不改变网站展示。限制：没有替换为更小图片时，总图片字节数不会仅因优先级调整而下降。

### B. 重新组织完整目录与询价数据

可以进一步减少某些路由的数据，但会涉及多个选型和询价入口。当前传输量与执行时间不足以支持优先承担这一改动范围，本轮不采用。

### C. 手机图片变体与字体裁剪

能进一步减少传输，但需要单独验证画质、字体字符覆盖及素材维护。本轮不重新处理图片或字库；若 A 收益不足，汇报实测后再确定下一批。

## 验收与安全边界

1. 在相同构建、设备与限速设置下比较至少三轮最终结果，并保存资源请求及时间数据。区分实验室测量与真实线上数据，不承诺排名或评分。
2. 不仅看 HTML 构建成功：确认三页无水合错误，手机无横向溢出，桌面与手机视觉没有改变。
3. 验证首屏图、轮播切换、移动菜单、USB 筛选、对比、询价清单以及刷新恢复；不向真实邮箱发送测试。
4. 无 JavaScript 仍有完整主要内容、样式、产品与资料链接；询价提交继续保持安全禁用。
5. 若增加模块预加载，校验根路径和 `/fahint-electric-website/` 子路径下的链接、静态页面文件及 404；不得把服务器构建文件放入公开 dist。
6. 先补最小回归检查，再实施；相关测试、完整现有测试和生产构建通过后才报告完成。
